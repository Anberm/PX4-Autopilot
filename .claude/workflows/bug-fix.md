# Bug 修复工作流

## 概述
本工作流定义了 PX4 Bug 修复的标准流程。

## 流程图
```
[问题分析] → [定位根因] → [实现修复] → [回归测试] → [代码审查] → [合并发布]
   COORD       专家          专家         TEST          PM          PM
```

## 详细步骤

### 阶段 1: 问题分析 (Coordinator)
**输入**: Bug 报告/Issue
**输出**: 问题分析报告

1. 收集问题描述和复现步骤
2. 获取日志和 Flight Review 链接
3. 分析影响范围
4. 确定优先级
5. 分配给对应专家

**问题分类**:
| 模块 | 分配专家 |
|-----|---------|
| Commander/Navigator/Sensors | PX4 Firmware Expert |
| EKF/控制器/ControlAllocator | Flight Control Expert |
| 驱动/板级配置 | Driver Expert |

**交付物**:
- [ ] 问题描述清晰
- [ ] 日志已获取
- [ ] 优先级已确定
- [ ] 专家已分配

### 阶段 2: 定位根因 (对应专家)
**输入**: 问题分析报告
**输出**: 根因分析

1. 复现问题 (SITL/硬件)
2. 分析日志数据
3. 审查相关代码
4. 定位问题根因
5. 评估修复方案

**交付物**:
- [ ] 问题已复现
- [ ] 根因已定位
- [ ] 修复方案已确定

### 阶段 3: 实现修复 (对应专家)
**输入**: 根因分析
**输出**: 修复代码

1. 创建修复分支
2. 实现修复代码
3. 添加必要注释
4. 本地验证修复

**交付物**:
- [ ] 修复代码
- [ ] 本地验证通过

### 阶段 4: 回归测试 (Test Expert)
**输入**: 修复代码
**输出**: 测试报告

1. 验证 Bug 已修复
2. 运行回归测试
3. SITL 仿真验证
4. 确保无新问题引入

**交付物**:
- [ ] Bug 验证修复
- [ ] 回归测试通过
- [ ] SITL 验证通过

### 阶段 5: 代码审查 (Project Manager)
**输入**: 完整 PR
**输出**: 审查通过

1. 创建 Pull Request
2. 关联原始 Issue
3. 代码审查
4. CI 测试通过
5. 获得批准

**交付物**:
- [ ] PR 创建
- [ ] Issue 关联
- [ ] 审查通过
- [ ] CI 通过

### 阶段 6: 合并发布 (Project Manager)
**输入**: 审查通过的 PR
**输出**: 代码合并

1. 合并 PR
2. 关闭 Issue
3. 更新变更日志 (如需要)
4. 考虑是否需要 backport 到发布分支

**交付物**:
- [ ] PR 合并
- [ ] Issue 关闭
- [ ] Backport 评估

## 优先级定义

| 优先级 | 描述 | 响应时间 |
|-------|------|---------|
| P0 | 崩溃/安全问题/阻塞发布 | 立即处理 |
| P1 | 重要功能缺陷 | 当天处理 |
| P2 | 一般问题 | 本周处理 |
| P3 | 改进建议 | 待排期 |

## 协作矩阵

| 阶段 | COORD | PX4 | FC | DRV | TEST | PM |
|-----|:-----:|:---:|:--:|:---:|:----:|:--:|
| 问题分析 | ★ | - | - | - | - | - |
| 定位根因 | ○ | ★ | ★ | ★ | - | - |
| 实现修复 | - | ★ | ★ | ★ | - | - |
| 回归测试 | - | ○ | ○ | ○ | ★ | - |
| 代码审查 | - | ○ | ○ | ○ | ○ | ★ |
| 合并发布 | - | - | - | - | - | ★ |

★ = 主要负责, ○ = 辅助参与, - = 不参与

## 日志分析指南

### 使用 Flight Review
```
1. 上传日志到 https://review.px4.io
2. 检查关键指标:
   - Estimator Status: EKF 健康状态
   - Vibration: 振动水平
   - Control: 控制响应
   - Position/Velocity: 位置跟踪
```

### 使用 pyulog
```bash
# 查看日志信息
ulog_info flight.ulg

# 转换为 CSV
ulog2csv flight.ulg

# 绘制参数
ulog_plot flight.ulg -t vehicle_local_position -f x y z
```

## 回滚机制

如果修复引入新问题:
1. 立即回滚修复
2. 重新分析问题
3. 制定新的修复方案
4. 更充分的测试验证
